# 销量趋势与竞争选品 · product.opportunity@2.0.0

这是新审核版本，不覆盖 v1 供货评分或既有冻结配置。固定脚本，不调用 LLM；在现有 `product.decide` 节点选用，不能替代 CJ 事实、系统核算、审批或接口发布。

## 证据

CJ `listedNum` 是刊登数量，不是成交销量：[CJ 商品文档](https://developers.cjdropshipping.com/en/api/api2/api/product.html)。当前未接入外部市场数据提供商，不能宣称自动取得销量。

在“定义商品任务”中选择或导入 `MarketEvidence@1` JSON（最多 50 个唯一 CJ PID），然后试搜。“评估商品机会与建议售价”选择 v2 并继承任务证据与估算开关，不重复设置来源。以后数据连接器可以交付同一结构。两个相邻 30 天窗口的商品销量和搜索量、竞争商品数量、竞品中位价、每单获客成本是必需事实；未知留 null，不能默认零。批次声明市场、币种、来源渠道、来源引用、观察时间、窗口结束时间；每件需 CJ 对应说明和 observed/estimated 销量标记。

试搜与正式采集先核验版本、市场、币种和有效期，再把限额 CJ 搜索结果与证据中的 PID 对应；只让已对应商品进入详情、库存和运费核验。未对应数量明确显示，没有对应则停在采集，不继续浪费后续请求。不扩大类目、翻页额度或以证据 PID 绕过原查询范围；不是按全 CJ 目录销量排序。完整分数和建议价仍须等成本与履约事实齐全后计算。旧冻结版本继续原节点配置，不自动迁移；上下游重复声明冲突时拒绝。

人工导入保存为不可变 MarketEvidence UUID、摘要和审计，`operator_import_unverified` 不表示系统独立核实。HTTPS 引用仅留作核验，不抓取；不得含凭证、查询参数。来源真实性与商品匹配需人工审查。国家/币种不匹配、采集或窗口结束超过七天、未来日期、重复 PID、摘要改变不能执行。旧证据不刷新时间；换证据须重新应用、保存并冻结新版本。数据不是类目平均销量，不将来源渠道表现直接等同目标店铺转化。

## 确定性规则

- 需求 30%：本批销量占比 70% + 搜索量占比 30%，各自以本批最大值归一化为 0–100。
- 趋势 20%：销量增长率占 70%、搜索增长率占 30%；增长率截断 -100% 至 +100%，映射为 0–100。历史为零给中性 50，不推断无限增长。
- 竞争 15%：100 / (1 + 竞品数量 / 20)。20 是版本化参考量，不是市场真理。
- 经营空间 20%：竞品中位价扣费率、到货成本与所填获客成本后的贡献率 × 200，截断 0–100。不是净利润，CAC 与费率可为假设。
- 履约 15%：总时效相对运营时效上限（70%）+ 可售库存/限售缓冲（30%，50 件饱和）；工厂供货总分再扣 10。
- 建议价 = (到货成本 + 所填获客成本) / (1 − 费用率 − 目标贡献率)，向上取整到美分。此版本目标贡献率是扣所填获客成本后的目标，v1 仍为广告前目标。

综合分只是批内相对规则排序，不是验证过的预测模型，不保证销量、售价接受度或利润。空销量/搜索、缺字段、估算销量未显式允许、建议价超过竞品中位价，均保留排除/待研究原因。没有合格候选，运行停在评估，不转核算。竞争越低不证明越有需求。

## 贯通与安全

冻结绑定 Skill UUID/2.0.0 和证据 UUID。输入及评分输出 Pydantic 校验；运行保存原观察、逐项分数、含广告建议价、未知项及来源摘要。系统核算独立重算建议价。后续每个执行/审核阶段重读证据并重算整份提案，摘要变化、过期或 Skill 停用阻止发布。提案摘要加入两轮批准；返工保留证据，不自动重新生成批准。

人工导入无论 observed/estimated，都强制两轮审批，关闭节点审核开关不能绕过。即便将已产出的 CJ 方案用于旧七步入口，MARKET_EVIDENCE 来源标识也维持人工审核。发布准备、店铺版本、幂等与可售核验继续原受信规则。

本机注册：`COMMERCE_ENV=local COMMERCE_DESKTOP=1 ../server/.venv/bin/python manage.py register_opportunity_skill --market`。仅注册已测试闭合代码版本，不覆盖旧版，不创建账号或伪造真实市场数据。测试使用合成市场证据、模拟 CJ 和临时数据库的真实测试站 API。
