# 客服与商品图：冻结业务流程

两条标准主线使用与选品一致的保存、冻结、运行工作台和持久化事件。
运行配置在原画布节点窗口设置，保存为首节点 `binding.parameters.runtime`。
支持手动启动及业务定时器中的标准客服七步、商品图六步；不是通用 DAG 引擎。
客服另支持持久化收件箱监听，每条真实消息一轮；参见 `workflow-scheduling.md`。

## 分层

- `registry/business.py`：Pydantic 配置、完整节点/连线、受信规则摘要与模型连接指纹检查。
- `runtime/business.py`：独立业务步骤处理，复用 WorkflowRun、Outbox、租约、revision 和事件。
- `agents/store_support.py`：HTTP 资料、固定检索或 Pi harness 回复、测试收件箱发送与回执。
- `agents/image_service.py`：原 ProductImageBatch、Pi 逐张方案及 Sunburst 生图执行器。
- `BusinessConfigurationWindow / BusinessRun`：配置、原画布运行、实际事件回放与明确确认。

不借用内容整理 SkillVersion 执行模型业务。该 FK 对这两种版本允许空值；模型规则引用与摘要独立冻结。
旧发布图仍要求已审核注册的确定性 Skill；不改变旧冻结快照、审批或发布幂等逻辑。
其他窗口仍可查看原客服归档和图片批次，不冒充新工作流运行。

## 客服七步

接收冻结消息 → HTTP 资料 → 固定检索 / Pi 回复 → 检查并人工确认 → 发送 → HTTP 回查 → 归档。

冻结具体消息、执行器、模型引用和测试政策确认；发送前核对获批内容未变。
缺事实或退款/取消/补发转人工；不授权支付、退款、采购、邮件或履约。
人工确认使用业务命令 revision、内容摘要及审计，不伪造选品 ApprovalRequest。
模型请求先登记唯一报告；失败或结果未知不能用“继续运行”重新请求模型，须明确启动新轮。
新配置可选择 `input_mode=inbox` 与 `reply_policy=automatic`：在定时器明确启用后，
普通政策咨询通过引用、资料与缺失项检查后，按冻结授权发送，审计不是人工批准。
旧版本缺省单消息、人工确认；不会因定时器或刷新被升级。失败/未知/转人工不自动重跑。
发送未知只查询原操作键，不重复发送。测试站回执仅说明保存在测试收件箱，非真人阅读。

## 商品图六步

选择冻结已上架商品 → Pi 制定方案 → 人工确认方案/费用后生图 → 文件检查 → 人工确认外观 → 素材包。

商品、原图来源、模型、Skill、尺寸、用途、张数与要求冻结；批次保存完整冻结设计快照。
逐张调用原执行器，不跳过源图校验、尺寸/摘要检查或外观确认。
停止保留在途结果及费用；未知模型/生图请求不自动重试。
交付素材包不替换线上商品图、不投广告；测试站归档仍为原独立明确操作。

## 恢复与验收

刷新 / 退出仅读取原运行 ID。手动执行原运行未结束时拒绝另起同业务。
收件箱监听每店铺串行执行；待人工消息单独留存，后续客户可继续处理。
引用失效、权限改变、规则或模型连接变更必须停止并重新确认，不回退其他店铺/模型。
CJ 历史研究清理不能删除客服发送未知或商品图在途证据。

`tests.test_business_workflow` 验证冻结、两次图片确认、原图执行器、停止、模型失败不重试、
获批回复变更阻断、实际本机 HTTP 客服发送/核对和恢复；模型及生图部分明确 mock，不代表付费服务验收。
