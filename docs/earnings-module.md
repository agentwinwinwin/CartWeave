# 收益模块 · 第一版

`/earnings` 展示净销售额、完整核实的订单运营利润、待补成本订单、净退款、每日趋势和订单明细。当前订单页面与测试站支付仍为模拟，自动订单、实际成本及广告连接器未实现；不得转成真实账目。无数据为“待接入 / 当前范围无账目”，不是已核实的零利润。

## 固定计算规则

- 净销售额 = 实收总额 − 代收税款 − 退款总额 + 退还代收税款。客户支付的运费包含在实收内，实际配送成本独立扣除。
- 广告前利润 = 净销售额 − 实际采购 − 实际配送 − 平台及支付手续费 − 其他实际费用。
- 运营利润 = 广告前利润 − 已归属本订单的实际广告费用。不是银行到账、会计净利润或所得税后利润；未登记的固定开支不在此范围。
- 任一必要费用为 null 时该层利润未知；明确 0 必须由来源确认，不能默认零。所选范围有任何不完整订单时不显示完整利润合计；广告前成本齐全时可单独显示广告前合计。
- 退款和成本补齐按原付款日期重新核算，非退款发生日的现金流水。退款不默认返还采购及配送费。金额使用 Decimal，首版支持 USD/EUR/GBP/CNY，分别统计，不自动换汇。
- 按用户选定 IANA 时区的付款日归属，查询使用半开区间。无账目日期留空，趋势不伪造零点。最多 93 天，订单明细每页 50 条。

## 后端接入边界

`apps.finance.OrderFinancialFact` 是不可变的实际订单账目快照。每个店铺 / 外部订单使用连续 revision，保存来源事件 ID、资料引用和观测时间；同一事件重复返回原记录，不允许以同一事件覆盖不同账目。更新采购、退款等追加新版本，汇总只读最新版本。付款日期或币种变更拒绝并要求核对，不删除历史。费用缺失可保存但不参与完整利润核算。

`record_fact(team,store,actor,payload)` 是未来受信订单适配器的内部接入点，使用 `contracts.finance.FinancialFact` 校验，并写审计。它不是已接入的自动采集器，不执行来源 URL、LLM、付款或采购；只有授权的团队身份可以写入。尚未提供公网写入、手填收益、文件导入或店铺 webhook。未来接入需验收真实支付与退款事实、订单 SKU 的实际成本分摊、费用完整性与广告归属，不能直接使用选品运费报价、建议售价或 CJ 销量。多币种订单费用需上游提供可审计换汇证据后才允许落账。

`GET /api/v1/earnings` 参数：start/end、timezone、currency、store、page。团队隔离，汇总包含整个筛选范围，不受明细分页影响；无 HTTP 写入入口。前端只展示该投影，不另建 localStorage 账目。迁移只新增财务表，不初始化示例收入、改密钥或清理运行。

## 后续范围（未实现）

真实订单与退款适配器 → CJ 实际订单采购 / 物流成本 → 实际渠道费用 → 明确广告费用归属 → 受信内部落账。商品维度利润需要订单项与实际成本分摊，当前没有该事实结构，首版不假造商品收益排名。固定费用、结算到账、汇率、会计账本和报表导出另行设计。
