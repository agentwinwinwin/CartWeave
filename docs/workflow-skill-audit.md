# 工作流 Skill 边界审查

## 原则

固定的是职责、输入输出契约、授权、责任方、预算和防重复规则，不是所有平台调用。接入接口因店铺、广告、仓库或客服服务而不同，应可替换 Skill；Skill 可以执行脚本或连接器，不必调用模型。前端清单和连接引用不证明部署、凭证授权或真实执行。

接口步骤保留必要职责，不开放运营删除/重排或提前结束；策略分析节点仍可按既有规则编辑结构。自选实现跨渠道保留，但不兼容时预检阻止模拟；不借用其他平台接口。所有真实条件由后端重新核验。

## 全部五条流程审查

| 流程 | 可配置的接口 Skill | 保留系统边界 |
| --- | --- | --- |
| 选品到上线 | 渠道刊登要求适配、商品上架、可售状态查询/事件 | CJ 采集固定；资料校验、规则筛选、CJ 配送核验、贡献核算；选品和最终草稿的两轮授权 |
| 推广与首次投放 | 广告草稿提交、审核结果、广告启动 | 提交必须暂停；批准素材和花费上限；未审通过不得启动 |
| 订单到交付 | 店铺订单事件、供应商/仓库履约、出库、店铺回写/通知、交付跟踪 | 真实付款/库存/地址资格、履约授权、实际出库证据与通知幂等；平台负责履约时只读 |
| 经营复盘 | 数据采集、批准调整的执行 | 数据新鲜度与样本核验、批准目标/预算/幅度及冷却期 |
| 售后解决 | 客服事件、证据读取、退款/补发/消息执行、结果确认 | 问题去重、真实订单事实、允许动作和分项授权、实际结果证据 |

选品、内容、宣传素材、经营建议和售后建议依旧可换策略 Skill。审批不能由 Skill 自报 approved=true 替代。契约吻合但动作影响、渠道或履约责任不吻合的实现仍拒绝。

## 本次已实现与未实现

接口适配与策略能力均保留兼容性、前置职责及权限预检。运营默认窗口现展示“接口接入”，店铺范围动作统一继承连接；单节点接口 Skill、连接覆盖和自建清单移至高级配置。一次性接入生成 Skill 负责开发完整接口包，而非逐节点重复运行；内容生成策略仍独立选择。本次未增加平台 API、执行器、认证或凭证存储，未产生任何外部动作。

后端 spec 必须进一步解决：

1. 统一系统校验与平台要求适配分层：平台检查 Skill 返回通过不能覆盖核心字段、素材和授权检查。
2. 广告平台、支付、仓库、物流和客服连接不等于销售店铺连接；当前 manifest.channels 只声明销售渠道适用范围，不足以证明服务商、账户或动作权限。需要独立 provider/connection 元数据与授权范围。
3. 发布 Skill 明确平台产品模型、SKU/变体映射、发布目标和版本；发布返回 accepted 不能转换为可售。可售 Skill 需真实查询或事件证据。
4. Webhook 签名、订单/问题去重、原始状态语义、日志与幂等须在受信服务端；字段格式合法不等于付款真实性。
5. 不同履约方案用不同接口；平台履约观察 Skill 不允许采购、支付或发送重复通知。CJ 找品固定不等于所有渠道订单强制 CJ 发货。
6. 混合“回写与通知”及“退款/补发/消息”目前仍是组合职责；后端须拆分动作权限、执行日志和幂等键，明确通知所有权，避免平台已通知又发送。
7. 运行开始绑定不可变图、Skill 版本、连接范围与审批摘要；换接口或更改草稿后重新预检，旧批准不能授权新的外部动作。

以上事项不是当前前端已经实现的安全保障，不把模拟成功描述为后端验证成功。
