# 测试独立站的业务联调

## 已实现的边界

原 `test-store.v1@1.4.0` 发布与只读同步契约不变。新增加
`test-store.testing@1.0.0`，作为本机桌面测试扩展独立验收，不重写旧冻结版本、店铺版本或映射摘要。
`GET /api/v1/integration-packages` 的 `testing_extensions` 导出同一份 Pydantic HTTP Schema。

工作台入口 `/test-store-lab`，测试独立站底部也提供链接。选择已有连接，明确确认测试政策后验收。
凭证只由服务端 TestStoreAdapter 持有。换连接版本或扩展契约后须重新确认，不能回退另一家店铺。

### 测试购买 → 经营复盘

选真实已发布商品创建测试购买。价格来自原刊登；数量不得超过刊登库存。固定虚构客户，
付款仅测试事件，不收款、不调用支付、采购或履约、不扣线上库存。采购/配送等成本留空为未知，
可显式填测试值。一个事务保存订单、客户及财务来源事件；同键同输入复用，不重复入账。

点击同步，复用原 orders.read / customers.read / finance.read；每次各一页最多50条。
再从复盘模块核算最近七天并归档。财务和复盘均报告 `test_fact_count`，
`test-store://` 来源不是实际经营收入。缺失成本不按零核算。

### 测试收件 → 回复 → 回查 → 归档

在联调台发送咨询，可关联同店铺测试订单。客服模块选择店铺、读取收件箱并选择消息。
资料经 HTTP 读取，包括固定 Northwind 测试政策、关联订单及上下文摘要。
fixture 是确定性提取，不调用模型；pi 只通过既有 Pi harness 执行，需实际配置模型。
引用不在检索白名单则失败；退款/取消/补发转人工，不赋予资金与履约权限。

确认后按固定操作键保存回复到测试站收件箱，再 HTTP 查询相同操作键与内容，成功才归档。
回执是 `stored-in-test-inbox`，不表示邮件已发送或真人已阅读。超时/未知不自动重发；
后续只核对原操作键。在途不重复领取，60秒过期发送只允许核对。
原独立报告保留历史；现在标准七步可生成真实冻结 WorkflowRun，由原 HTTP 执行器处理。自动渠道收件/定时客服仍不支持。

### 商品图 → 素材包 → 测试站归档

原六步 ProductImageBatch 与 Pi/Sunburst 逻辑不改。已人工确认的 delivered 素材包
提供“归档到测试站”：按商品原 ChannelListing 复用店铺，将实际 PNG 经 HTTP 传到对应测试站。
站点验证摘要、PNG、尺寸、所属商品及操作键；素材单独持久化，不改 PublishedProduct.payload
或原发布 digest，不替换线上图、不投广告。重复点击先查询原操作键，内容不一致拒绝。

## 验证与未验收事项

`tests.test_store_testing` 有临时数据库、真实 TCP HTTP 服务器回归，覆盖订单/客户/财务、
客服七步和完整商品图确认后 HTTP 交付，同时检查原发布摘要不变。
商品图测试的模型与生图提供商是明确的 mock，不能当作付费模型或视觉保真度验收。
没有配置实际模型凭证时，不能宣称真实 Pi 推理及 Sunburst 全链已完成。

测试扩展仅 LOCAL + DESKTOP_MODE；生产不开放。仅已有工作区授权人员可启用/造测试数据；
独立站 Bearer 绑定单个 ApiClient，读取、关联订单、素材与回执均按该店铺隔离。
不上传数据库、虚构/真实经营记录、素材二进制、登录态或凭证到开源副本。
# 工作流执行入口

选品、标准客服七步及商品图六步均使用“保存配置 → 校验并冻结 → 运行”，但各用独立处理器，不调用错误的发布职责。客服 / 图片配置和原画布执行共用冻结版本、事件与返回入口；客服回复与素材包沿用原业务归档。商品图费用及外观明确人工确认，客服须检查并确认发送。经营复盘仍为独立只读报告，不冻结自动调整。其他未实现图仍只能保存预览，定时客服 / 生图暂不开放。详见 [业务运行说明](business-workflow-runtime.md)。
