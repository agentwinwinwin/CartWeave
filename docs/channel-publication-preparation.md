# 渠道发布准备与发送的职责

原画布：最终草稿审核 → 准备渠道发布数据 → 提交渠道发布 → 可售确认。

## 准备节点

运营一次选择店铺及已安装映射方案（目前由接口包提供一个内置方案），锁定包版本与连接版本。第一次接入的模型分析在开发设置中进行；分析草案不是可执行方案。

日常执行的目标：读取已批准商品及真实业务事实，调用已审核的确定性映射代码，检查目标接口必填字段、类型与业务约束。保留批准摘要、请求摘要、店铺、连接版本及方案版本。缺字段返回具体路径与原因，停止，不猜值、不发请求；需要补充商品内容时必须重新检查与审批。

输出设计契约 PreparedChannelPublication@1：approvedListingRef、approvedDigest、storeRef、connectionVersion、mappingPlanRef、mappingPlanVersion、requestArtifactRef、requestDigest、checkedAt。实际请求应存服务端私有产物，不把凭证放入产物或草稿。

## 发布节点

只读继承准备结果，不再提供另一套店铺或 Skill 配置。服务端执行前重新核对包注册状态、连接版本、权限、审批内容及两个摘要；任何不一致返回准备步骤。使用持久化操作标识提交，处理回执；未知结果先按原标识查询，不盲目重新生成键重试。接受回执不等于可售。

## 本次实现边界

已实现：画布职责和契约草案、准备窗口配置、发布窗口只读继承、绑定不一致预检拒绝。旧草稿参数不自动迁移。

未实现：完整 v2 执行器、PreparedChannelPublication 的服务端产物和运行时校验、新的独立准备执行步骤。Django 仍运行原七步测试站主线，内置检查/发布不冒充新节点已经执行。发布窗口折叠区的联调只用于旧链路验收；本次不新增测试商品或调用 LLM。Amazon 仍未安装真实受信适配器。
