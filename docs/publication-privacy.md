# 公开源码，不公开工作区

本项目的代码仓库与本机工作区是两个不同的交付物。公开源码不代表公开使用者的业务数据。

## 不进入仓库

- `backend/.local/` 及其他 `.local/`：密钥、内部凭证、数据库、备份、运行与审批事实、店铺配置、浏览器配对和行情方案。
- `.env*`（仅无密钥的 `.env.example` 可公开）、私钥、数据库及数据库附属文件。
- `data/cj-intelligence/`：本机采集快照。回归测试使用 `scripts/fixtures/` 的合成样例。
- 历史原型图片、构建目录、测试报告、日志和虚拟环境。

不要为了发布仓库删除本机数据库，不要把生产数据复制成测试样例。真实客户、订单、收益、店铺标识或凭证不能放入截图、录屏、Issue 和日志。

## 每次发布前

1. 检查 `git diff --cached --name-only` 和忽略规则，运行 `node scripts/check-publication.cjs`；不使用无检查的 `git add -f`。
2. 扫描暂存文件中的密钥、真实邮箱、账号标识和个人电脑路径。自动扫描不能代替人工检查。
3. 检查图片、ZIP、JSON 和其他非代码文件；截图只使用合成数据或经过确认的脱敏数据。
4. 检查提交作者、邮箱和远端地址。需要匿名时使用独立公开账号；不要配置真实邮箱为提交邮箱。

GitHub 会公开仓库所属账号以及提交作者。这不包含本机登录密码，但仍是公开身份信息。请勿把“不上传工作区隐私”理解为“GitHub 账号本身匿名”。

若密钥曾误传，删除文件或补一条提交不能使它失效；必须立即撤销密钥，并另外处理 Git 历史、缓存和已有副本。
