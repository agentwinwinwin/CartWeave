# 商品机会与售价建议 · product.opportunity@1.0.0

这是受信后端的确定性选品 Skill，不是 Codex 接口开发规则，也不调用模型。选择入口为工作流“评估商品机会与建议售价”；“我的技能 → 已注册版本 → 选品策略”可查看算法。用户既有配置和已冻结版本不自动改写。

## 算法框架

仅处理前序库存与配送核验通过的真实规格，不生成商品事实。到货成本使用系统提供的供货价、运费、报价税费与运营明确税费预留；对税费及清关费使用预留和报价之较大值，并保留总邮费下限。总时效包含工厂备货。

- 成本分：本批最低到货成本 / 当前到货成本 × 100。
- 时效分：本批最短总时效 / 当前总时效 × 100；计算时最低按一天。
- 库存缓冲分：min(可售限额 / 50, 1) × 100。50 是固定参考量，不是需求估计。
- 综合分：成本分 × 60% + 时效分 × 25% + 库存分 × 15%，工厂供货扣 10 分，下限零。工厂限售量不是已核实库存，扣分不能替代强制人工核验。
- 同分按成本、时效、规格 ID 依次排序。分数仅在本批候选内比较，不是跨任务的绝对商品质量。先选一件，其余排序与证据保留。
- 建议售价：到货成本 / (1 − 合计费用率 − 目标贡献率)，向上取整到美分。系统核算节点独立计算并核对一致才继续。

销量、需求、竞争价格、广告获客成本明确未知。算法评估供货可行性，不预测好卖、不保证市场接受价、不将广告前贡献称为净利润。当前权重及参考库存固定在审核代码版本内，修改须新版本；业务费用与目标贡献率继承系统核算节点，不重复配置。

## 运行边界

输入候选经 Pydantic 校验；空候选、缺事实及重复规格拒绝。结果保存评分明细、建议售价、未知项、版本 UUID、代码摘要及来源证据。注册表实时核对团队、审核、停用与代码摘要；停用阻止后续执行。保留税费缺失阻止、报价一小时有效期、两轮审批、冻结店铺版本、准备发布及幂等回执核验。

旧 `product.decision.landed-cost@1.0.0` 保留历史成本优先排序，不自动升级。内容整理代码摘要未修改，现有内容批准版本保持有效。新算法通过闭合 registry 扩展，不提供上传脚本或动态执行入口。

本机安装使用 `COMMERCE_ENV=local COMMERCE_DESKTOP=1 ../server/.venv/bin/python manage.py register_opportunity_skill`，仅复用已有唯一工作区所有者，创建此已审核版本及审计，不新建账号、不覆盖或恢复停用版本。团队部署通过已有注册与审核 API；能力、入口、版本必须匹配。

回归包括评分、确定性同分、价格、工厂扣分、缺失输入、全十五步两轮审核后调用真实测试站临时数据库接口，以及中途停用阻止发布。CJ 回包模拟，不宣称已对真实市场验证策略收益。
