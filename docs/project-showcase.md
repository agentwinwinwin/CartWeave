# 项目讲解与演示提纲

## 30 秒介绍

CartWeave 是一个可自托管的跨境电商工作流工作台，按选品、商品图、推广、订单、经营复盘和客服组织业务，而不是把所有动作塞进一条流水线。Next.js 提供同画布配置与执行视图，Django DRF 和 Pydantic 管理固定契约、冻结版本、权限与恢复；官方 Pi Agent Core 承接真正的模型调用。已实现 CJ 到测试站发布，以及本地测试站客服、商品图和订单物流标准执行器；客服按新消息持续触发，空闲不调用模型。真实资金、物流、邮件和广告仍未接入。

## 可写入简历的项目描述

设计并实现可自托管的跨境电商工作流平台，采用 Next.js + Django DRF 模块化单体与 Pydantic 版本化契约，建立六类业务模板和固定规则、可调参数、可插拔策略的分层；实现选品发布、测试站客服与物流闭环、商品图批次执行、冻结快照、Outbox、幂等外部操作和增量同步；接入官方 Pi Agent Core，统一模型会话与接口分析；基于持久化游标和共享消息领取实现事件驱动客服调度，与确定性业务隔离。

## 面试可深入的四个问题

- **为什么不用 LLM 执行所有节点？** 稳定数据转换和业务规则需要可验证与可回放；模型适合处理首次接口差异，不适合补编库存、订单数或运费事实。
- **重试为什么不会重复上架？** 外部操作键、持久化意图、回执查询与状态核对协同；未知结果不立即生成新键盲目重发。
- **如何通用而不抽象过度？** 保留运营可理解的动作职责，平台差异下沉到契约适配层；固定输入并不意味着所有平台原始接口相同。
- **如何扩展并发？** 当前本机 SQLite 单 worker；后续数据库迁移、任务领取锁、限频共享、租约与幂等压力测试需一起验证，不能只按 CPU 核数加 worker。
