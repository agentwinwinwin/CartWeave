# 前端设计检查与开源展示基线

## 定位与范围

CommerceOS 面向可分发、可自托管的开源运营工作台，不将“某个人的私人应用”作为产品定位。本机桌面模式是部署模式，团队身份与授权仍由原后端管理；本次不新增管理员、切换鉴权或开放渠道执行权限。

检查路由：工作流总览、设计器、真实运行、接口映射、商品、订单、客户、技能、运营助手、CJ 接入和测试站。测试站保留 Crownley 既有品牌，不套用运营工作台样式。

## 视觉原则

参考 Apple Human Interface Guidelines 的清晰层级、对齐、可读性与内容优先原则，不声称由 Apple 设计师设计。导航用轻质背景区分控制层；表格与画布保持不透明，避免透明材质干扰业务事实。

- 令牌：`app/globals.css`，系统字体、中性背景、语义化状态色、统一焦点与选中态。
- 共享组件：Button / Input / SelectField / Card / Badge / StatCard / DataTable；统一线性 Icon，FeatureNotice 用于解释模块支持范围。
- 顶部导航：真实链接、当前页语义、工作区模式与跳转主内容；不显示虚构用户、通知或不可用搜索。
- 窗口：原生 dialog 顶层，明确标题、滚动内容、固定保存区域、Escape 关闭与焦点恢复。不增加另一套画布。
- 响应式：桌面 1440 / 1100，窄屏 760 / 390；表格内部滚动，配置窗口不越过视口。

## 页面改进

| 模块 | 本轮调整 | 功能边界 |
| --- | --- | --- |
| 工作流 | 压缩重复提示、统一卡片和工具栏、保留三种节点权限视觉、修复卡片标题收缩 | 不更改图结构、冻结版本或执行 |
| 商品 | 更清晰的主图与标识、说明折叠、统一表格与空状态 | 仍来自真实发布记录，下架仍需确认 |
| 店铺 / CJ 接入 | 表单字号、状态层级与窗口布局、类目复选框尺寸 | 不改变密钥保存或验收权限 |
| 接口映射 | 模型表单分组、固定契约与说明层级 | 分析草案不代表已安装适配代码 |
| 技能 | 清晰的规则 / 注册版本 / 草稿分区、对齐规则卡片 | 不恢复技能市场，不将草稿当执行版本 |
| 订单 / 客户 | 复用 DataTable、可用筛选、键盘查看与关闭详情 | 明确示例数据，不虚构真实统计或物流事件 |
| 运营助手 | 安静的起始状态、问题草稿、真实工作区入口 | 未接入对话执行器，不伪造运营提醒或模型响应 |

## 验证

- `npm run build`：类型检查与生产构建。
- `npm run test:workflow`：流程契约、绑定和默认参数不变性。
- `scripts/audit-frontend.cjs`：11 路由 × 4 视口，只读请求、异常与页面溢出检查、截图。
- `scripts/test-frontend-interactions.cjs`：筛选、空状态、键盘选行、草稿清空、节点标题高度、窗口关闭与响应式；禁止后端写入。
- `scripts/test-launch-browser.cjs`：全拦截模拟的同画布运行、断点恢复和两轮审批回归，不代表真实外部发布验收。

两个新增浏览器脚本需要可解析的 Playwright（开发依赖或 `NODE_PATH`）。可用 `FRONTEND_URL`、`CHROME_PATH`、`FRONTEND_AUDIT_DIR` 指定服务、浏览器与截图目录；默认使用临时目录，不依赖开发者用户名。只读检查不恢复或批准真实运行。

2026-10-03 本轮结果：生产构建通过；工作流 74、技能 6、测试站 3 项测试通过；11 路由 × 4 视口未发现客户端异常或页面级溢出。交互检查覆盖筛选、空状态、键盘选行、15 个节点标题、Escape 关闭与焦点恢复、店铺接入窗口响应式；同画布完整发布的模拟回归通过。真实外部订单、广告、Amazon 发布不在本轮验收范围内。

## 执行态改版（2026-10-03）

参考 [n8n](https://github.com/n8n-io/n8n) 的运行上下文、[Trigger.dev 时间线](https://trigger.dev/changelog/run-page-timeline) 与 [Kestra 执行详情](https://kestra.io/docs/ui/executions) 的分层组织，独立实现 `RunExecutionView`，不引入其引擎或复制源代码。

- 设计器切换为摘要 + 原冻结画布 + 节点详情；节点点击查看记录，不弹配置框。返回编辑不取消任务。
- 进度 / 结果 / 事件分区：当前阶段使用真实计数和尝试时间，非当前节点显示本轮已有记录；未知计数不填零。
- 商品数与规格数分开展示。待研究原因来自服务端结果；一个规格可能有多个原因，不合计成排除总数。
- 人工审批、受控修订、恢复与取消复用原有命令，资料摘要优先展示，完整输入主动展开；不自动批准或启动外部重试。
- 运行级结果明确标注，不假装是所选节点独立输出。没有返回事件时显示空状态。
- 桌面画布和详情区分别滚动，不将 15 个步骤的侧栏拉成长页；默认跟随当前节点，主动查看其他节点时停止跟随。窄屏转为上下布局，尊重减少动态效果设置。
- 验证：生产构建及 74 项工作流回归通过；全拦截模拟覆盖启动、唯一画布、节点不弹配置、真实计数更新、旧研究暂停结果、断点恢复和两轮审批；390 / 760 / 1100px 未溢出。通用交互与 11 路由 × 4 视口检查也通过，不代表真实外部发布验收。

## 执行动效（2026-10-03）

- 运行节点使用共享 `WorkflowCard` 的冷蓝色巡边、柔和呼吸和状态灯；运行色与可配置 Skill 的紫色权限标识分开。完成、暂停、审批不使用循环巡光，协作仅作用于已标记的参与节点。
- 共享 `WorkflowConnection` 使用柔光轨道、白色光芯与分层粒子；仅传递事件激活光束，处理期间不点亮下一条线。粒子与线段共享 `transmissionDuration`，线段尖端精确从路径 0 移至 100，不以视觉动画推进业务游标。
- `prefers-reduced-motion` 停止巡边、呼吸、状态灯与光束移动，保留静态状态；SVG 装饰不拦截点击、不进入辅助技术朗读。
- 验证：生产构建与 74 项工作流测试通过；全拦截模拟回归验证单节点处理、无提前传递、传递线段实际移动、暂停停止以及减少动态效果，并继续覆盖断点恢复和两轮审批。未执行真实上架。

## 后续限制

### 默认可执行策略

- 商品任务以“选品依据”展示默认 CJ 说明和最低销量；外部证据、供货评估放入高级设置，解释随来源切换。移除重复绑定按钮和固定“已接商品源”文案。
- 显式来源切换在应用时同步绑定已审核策略：CJ v3、外部 v2、供货 v1。保留类目、市场、店铺、数量等参数；取消不改原配置，切离外部证据时才清理不兼容引用。临时切换后的只读试搜不发送其他来源的证据引用。
- 单测覆盖三个来源的原子更新、原文档不变、缺批次/不兼容版本拒绝；全拦截浏览器覆盖供货 → 外部缺证据禁止应用 → 取消 → CJ，随后继续原冻结与运行回归。不触发实际发布。

- 默认选品和内容占位统一在加载/保存前读取受信注册表解析：未指定证据来源时设置 CJ 来源并绑定可执行 v3；已有外部证据保留并绑定 v2；内容默认原素材整理。只有 approved、selectable、版本及契约匹配的登记版本可用。
- 仅修正未调整的默认占位及其原始演示参数；显式策略、注册版本、自定义指令、明确禁用证据和冻结运行不覆盖。缺注册版本、冲突或自定义参数停止，不回退示例算法，不删除证据设置。
- 回归覆盖 v3 来源联动、v2 外部证据继承、停用/缺失版本拒绝、自定义参数保护及两种默认 Skill 一起保存。当前用户保存配置的副本，经此默认绑定后的完整十五步通过服务端 `validate_document`；只读验证，不创建冻结版本、运行或外部商品。

### 编辑与运行切换

- “返回编辑”仅隐藏运行面板，保留其冻结版本、任务 ID 与轮询。编辑保存后可点击“返回当前运行”，不再次冻结、不 POST 新任务；编辑参数不影响原任务。
- “启动新运行”是单独的明确操作，保存并冻结当前草稿后创建另一轮；后端活跃任务限制继续生效。前端本地演示导致面板重新挂载时，以原任务 ID 读取并核对冻结版本，失败不自动创建替代任务。
- 浏览器全拦截回归覆盖退出、修改并保存、返回同一任务；检查运行创建请求仅一次，原冻结文档不变。此切换状态限当前页面会话，不代表刷新或跨页面的历史恢复功能。

订单、客户和对话执行器仍需真实后端接入；开源发布前还应独立审查许可证、README、环境配置、敏感文件和测试站素材使用范围。设计改版不代表已完成发布审计。业务未知值必须继续显式保留，不能为了漂亮界面制造成功状态。
